\section{Study 2: evaluating a model analyst before admission}
\label{sec:results-analysts}

Study 2 asks what a TRE can learn about a model analyst before admitting it: how often the model draws a wrong conclusion when the data invite one, what changes that rate, what a second model adds as a checker, and whether a configuration chosen on development tasks holds up on sealed ones (Figure~\ref{fig:design-evaluation}). The last two subsections take models into the gateway itself.

\subsection{Errors by model size}
\label{sec:results-harvest}

With the standard instruction, larger Qwen3.5 models drew fewer wrong conclusions on the dev tasks (Figure~\ref{fig:harvest}a). Unreported multiplicity stayed common at every size. Plotted against the same models' detection as reviewers at \level{0}, only the 27B combines few wrong conclusions with high detection and few false alarms (Figure~\ref{fig:harvest}b); the 2B to 9B models detect more errors than they commit only because they also flag nearly half or more of the correct reports. The relation did not carry across families, since models with similar detection of planted errors differed widely as analysts.

\subsection{Analyst prompts}
\label{sec:results-prompt}

The design-first prompt gave the most consistent improvement (Table~\ref{tab:prompts}; Figure~\ref{fig:prompt}a). Held-out tasks were harder than dev (Figure~\ref{fig:prompt}b), above all where recognizing regression to the mean required reasoning from the design because the tables held no comparison group. The checklist improved held-out performance. The design-first prompt helped on both sets, and with a 1,024-token thinking budget it brought Qwen3.5 27B, 35B-A3B and 122B-A10B to the same pooled error rate within overlapping intervals, and the smaller 9B stayed worse. Among these three, extra size gave no consistent advantage once the prompt and the thinking budget were set, which does not show that size is irrelevant in general.

Gemma did best without added thinking, and gpt-oss 120B improved under its vendor's sampling settings and high reasoning effort, while the same sampling change did not help Qwen3.5 27B. Reasoning settings therefore need testing for each model.

\subsection{Thinking budgets}
\label{sec:results-thinking}

A thinking budget helped the checkers more consistently than the analysts (Figure~\ref{fig:thinking}a, b and c for the checkers, Figure~\ref{fig:thinking}d for the analysts). A short budget let every Qwen3.5 size from 4B upward detect every wrong-denominator report on the first set of datasets (Figure~\ref{fig:thinking}c). The smaller models still failed on attrition or on false alarms. Several larger configurations met the detection threshold, among them a stepwise instruction that requires written working with no hidden thinking, and gpt-oss 20B at medium effort (Appendix Figure~\ref{fig:checker-full}a; Figure~\ref{fig:checker-full}b shows the same checkers on the analysts' real write-ups). What thinking fixed was an arithmetic failure, not a size threshold.

On a second set of datasets with twenty replicates, gpt-oss 20B and the stepwise Qwen3.5 27B again met the threshold, whereas Qwen3.5 27B with a short thinking budget kept full detection but exceeded the false-alarm limit there and on a third set. Assertiveness-matched correct reports also raised gpt-oss's false alarms, which again points to writing style.

\subsection{Transfer, and confirmation on sealed tasks}
\label{sec:results-sealed}

Development performance overstated how reliable a pipeline was: all three pipelines chosen by the first rule failed on the held-out tasks despite strong dev results, and the prompt transferred better than the checks chosen with it. Searching many combinations of stages on a small task set leaves ample room to select on chance (Appendix Figure~\ref{fig:frontier}).

The second rule pooled dev and held-out and fixed the configurations before the first sealed set was opened. Three pipelines were confirmed under the primary judge: Qwen3.5 122B-A10B, 27B and 35B-A3B, each with the design-first prompt, a short thinking budget and gpt-oss 20B at medium effort as checker (Table~\ref{tab:fresh}; Figure~\ref{fig:fresh}a). Both other judges supported those outcomes. Configurations that had done well on an earlier set regressed.

The same three analysts also met the planted-error criterion on the first sealed set without a checker. Adding the checker reduced wrong releases but withheld some correct answers and about one control task in six (Figure~\ref{fig:fresh}b). The analyst-alone comparison on this set is exploratory, because the registered test was of the analyst with its checker.

\subsection{Checking analysts' real errors}
\label{sec:results-crosscheck}

Strong detection of planted errors did not carry over to analysts' real write-ups. On the dev write-ups that all checkers read, AUC was far lower (Table~\ref{tab:crosscheck}; Figure~\ref{fig:auc}a). The more aggressive configurations withheld more of the write-ups the judge called wrong, but also more of those it called right. Thinking and access to the tables helped a little; size beyond 27B did not. The models with near-perfect AUC on planted errors lost about 0.3 of AUC on real write-ups.

Qwen3.5 27B also found fewer of its own errors than of other models' errors, with and without thinking. The effect was weaker for the 9B and absent for gpt-oss 20B. This is an association, not an isolated effect of model family, since the errors being compared differ too. Appendix~\ref{app:example} shows one such failure of self-review on a singled-out subgroup.

AUC measures ranking, whereas a pipeline's wrong-release rate depends on how often the analyst errs and on which of its errors the checker catches. The strongest analysts left too few wrong write-ups for a precise AUC. A pipeline can therefore release few wrong conclusions although its checker's AUC is weakly estimated (Figure~\ref{fig:auc}b). Its practical cost is the correct work it withholds (Figure~\ref{fig:auc}c). A second checker added little.

These estimates also depend on the judge: judges sometimes disagreed, and some checker objections concerned faults outside the scoring rubric.

\subsection{Judge agreement}
\label{sec:results-judges}

The two hosted judges agreed on \N{judges.pooled.agree} of the dev and held-out write-ups that both scored ($\kappa=\N{judges.pooled.kappa}$). On the first sealed set all three pairs of judges agreed substantially but differed in severity, MiMo pro being the most lenient. The local gpt-oss judge was harsher on the gpt-oss analyst than the other judges were, despite the shared family. On the second sealed set, agreement was lower on control tasks than on planted-error tasks, which reflects disagreement over how much caution is acceptable (Table~\ref{tab:fresh2}).

A hosted frontier model, GLM-5.3, run once as analyst showed the answer keys to be broadly reachable, with its errors concentrated on one task that local models also found hard; that task awaits human review.

\subsection{Statistical tools and prior planning}
\label{sec:results-nohelp}

Neither of two further interventions reduced wrong conclusions consistently across dev and held-out (Appendix~\ref{app:interventions}). Statistical tools removed arithmetic mistakes and introduced inferential ones: analysts attached precise tests to fragile comparisons, including imputed outcomes and uncorrected subgroups. Having a hosted model rewrite each request from the structure of the tables, without their values, helped the standard-instruction analyst on held-out but hurt the design-first configuration, because a plan fixed before the values were seen could favor a comparison that proved confounded. These results concern the tools and integrations tested; they do not show that statistical tools or prior planning are useless in general.

\subsection{Turning a request into a typed query}
\label{sec:results-planner}

With the dataset semantics stated, the local-class planner matched the intended query on \N{planner.local.primary.stated} of answerable requests, within one request of the demonstration's planner, and stating them raised its accepted share from \N{planner.local.accepted.omitted} to \N{planner.local.accepted.stated} (Table~\ref{tab:planner}). A model of the class a TRE could host locally can therefore do this job, and the change that mattered was to the prompt, which carries no safety obligation because the planner is untrusted. Neither planner reliably refused what the query language cannot express. Under both prompts both answered a different, permitted question instead (Box~\ref{box:planner}). The local-class model refused outright when a request was plainly for rows or timestamps, which is why its rejected share is higher, but it substituted on the subtler requests as readily as the other. A substituted answer is safe but misleading, so refusal has to come from the gateway, and an analyst that assembles many answers must report such a step as not answerable.

\subsection{End-to-end operation in the gateway}
\label{sec:results-e2e}

Both candidate analysts also ran as the inside analyst of the \sys{safe-tre-agent} gateway, version 0.13.0~\cite{wade2026safetre}, on NIGHTPLAY, a synthetic study of late-night phone use, gambling, giving and wellbeing kept with the gateway's code. The truths a competent analyst should find and the traps an incompetent one falls into were decided first, and the population was generated to hold them. Each of its nine questions has an expected verdict and a list of marks that an executable marker scores from the analyst's typed output alone. Here the analyst does not receive tables: it asks the gateway for them, one typed aggregate query at a time, and the gateway applies disclosure control to each answer. The questions include ``Is late-night phone use linked to gambling?'', a planted association; ``Is late-night phone use linked to charitable giving?'', a planted null in which heavy phone users include fewer high earners, so the raw link is an artefact of income and vanishes within every income band; and ``Does the association survive adjustment for employment pattern? Is it plausibly causal?'', which requires an adjusted model that the gateway refuses when a category is too sparse. With the design-first prompt and a short thinking budget they answered \N{chimp.q35.rules.verdicts} of 27 question-repeats correctly (35B-A3B) and \N{chimp.q27.rules.verdicts} of 27 (27B). Every miss came from stopping after the gateway refused an adjusted model over a sparse category, rather than revising the analysis. The runs show that the analysts operate in the gateway on one question bank, but not the recommended analyst-plus-checker pipeline, because NIGHTPLAY has no checker stage.
